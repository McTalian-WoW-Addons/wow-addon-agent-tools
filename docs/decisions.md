# Decisions

**A. Sharing mechanism — plugin repo that is its own marketplace.** New public repo `McTalian-WoW-Addons/wow-addon-agent-tools` cloned at `~/code/wow-addon-agent-tools`. Root `.claude-plugin/marketplace.json` (name `mctalian-wow-addons`) lists one plugin `wow-dev` at `./plugins/wow-dev/`. Each consuming repo commits `.claude/settings.json` with `extraKnownMarketplaces` (GitHub source) + `enabledPlugins: {"wow-dev@mctalian-wow-addons": true}`, so a fresh clone/CI/another machine gets it with zero manual steps — same shape as `wbt-configs` in `trunk.yaml` and `@v1` reusable workflows. Local development: `claude plugin marketplace add ~/code/wow-addon-agent-tools --scope user` registers the same marketplace name from a local path; because `extraKnownMarketplaces` only adds names not already known, this machine resolves to the working copy while everyone else resolves to GitHub. Symlinks rejected (not discoverable across machines, no versioning, break on Windows-side checkouts); submodules rejected (per-repo pin churn, `.claude/` would need to be the submodule root). Versioning via `plugin.json` `version` + `claude plugin tag`.

**B. Per-repo context contract — auto-detect first, JSON override second, prose last.** A plugin script (`repo_profile.py`) derives everything detectable: addon dir (from `<X>/<X>.toc`), flavors (from `## Interface`), test/i18n/trunk/toc-check/untracked-check presence (from `.busted`, `<Addon>/locale/`, `./trunk`, Makefile target names), CI wrappers (grep `uses: McTalian-WoW-Addons/wow-build-tools`), repo kind (`addon` / `lib` when tests but no `.toc` / `go-tool` when `go.mod`). An optional `.claude/repo.json` overrides only what cannot be detected. Prose for the model lives in exactly two places: `CLAUDE.md` with three fixed headings (`## Commands`, `## Conventions`, `## Docs`) so shared skills can cite them, and `docs/agent/conventions.md` (imperative must-obey rules the implementers and `lua-convention-reviewer` load on demand). Rationale goes only to `docs/agent/decisions.md`, never read by skills.

**C. Script runtime — Python 3.12+, stdlib only, run via `uv run --no-project`.** Every addon Makefile and `trunk.yaml` already requires `uv`; the org's existing tooling scripts (`wago_lookup.py`, `scripts/i18n/*`) are Python; nothing here needs a package so no venv/lockfile is created. Invocation shape everywhere: `uv run --no-project "${CLAUDE_PLUGIN_ROOT}/scripts/<name>.py" <subcommand> [flags]`. Hooks call the same scripts (JSON on stdin). Tests use `unittest`, run by `uv run --no-project python -m unittest discover -s plugins/wow-dev/scripts/tests`. Node rejected (only lumberjackd uses it; not installed in CI images for these repos); Go rejected (compile step, binary distribution inside a plugin).

**D. Skill set v1 — seven shared, two RLF-local.** Shared: `run-checks`, `git-workflow`, `work-item`, `review-pr`, `wow-api`, `add-locale-key`, `onboard-repo`. RLF-local: `wago-datamining` (slimmed), `add-feature-module`. This is the daily loop (change → checks → commit/PR → self-review, plus the two lookups that happen mid-change: API signature and locale key) plus the one skill that makes the layer spread to the other eight repos. v2: `address-comments`, `toc-bump`, `release-verify`, `add-roster-agent`, RLF `add-config-option`, RLF `faction-icon-audit` (currently a section of `wago-datamining`).

**E. Agent roster v1 — nine agents, one `ROSTER.md`.** Researchers: `wow-api-researcher` (sonnet/low — flavor-difference and deprecation judgment beyond raw lookup), `impl-researcher` (haiku/low). Implementers: `lua-feature-builder`, `spec-author` (sonnet/medium, only two with Edit/Write). Reviewers: `lua-convention-reviewer`, `localization-reviewer`, `commit-type-reviewer` (sonnet/low — checklist against a doc or a script's JSON), `skill-prose-reviewer` (sonnet/medium — adjudicates prose across files). Verifier: `claim-evidence-reviewer` (sonnet/medium). No opus in v1: no agent cross-checks a diff against a large body of settled decisions yet. Single `ROSTER.md` with four H2 sections instead of four files: nine entries do not justify four files, and skills cite `ROSTER.md §Reviewers` etc. Trigger paths use the placeholder `<AddonDir>` resolved from `repo_profile.py`.

**F. Workflows — none in v1; all mechanism is plain Python, all orchestration is prose.** With four reviewers, "spawn every applicable reviewer in one message" is one prose line; a `*.workflow.js` would add authoring/testing surface and depends on Workflow-tool opt-in that only holds when the user invoked the skill. Promote `review-pr` Stage 3 fan-out and `work-item` Stage 7 to `workflows/review-fanout.workflow.js` in v2 when the roster exceeds ~6 reviewers or a refutation pass is added. Deterministic multi-command sequences (checks, commit typing, PR lint, API grep, locale insert, doc lint) are scripts from day one.

**G. Hooks — exactly one `PreToolUse` on `Bash`, `guard_commit.py`.** Blocks (exit 2) a `git commit` when: on `main`; `--no-verify` present; untracked files exist under the packaged dir (the silent in-game build breaker); staged packaged-dir content differs from the index hash recorded by the last successful `checks.py` run; or `-m` type is a publishing type (`feat|fix|perf|locale|toc`) while no packaged file is staged. All five are deterministic; the message names the fix (`/wow-dev:run-checks`, `/wow-dev:git-workflow`). No `Stop`/`SessionStart` hooks in v1.

CLAUDE.md rewrite.** `~/code/CLAUDE.md` → ≤2048 B: workspace map by group (no table), `make` entry-point rule, plugin pointer, commit-type one-liner pointing at the skill, precedence rule, compressed caveman directive (override §0). ## Displaced rationale

Appended by implementers when rationale is removed from hot-path files.

### Why `checks.py` runs `./trunk check --no-fix`
`./trunk check` prompts "Apply formatting (Y/n/all/none)" and, when stdin is not a TTY, defaults to applying every fix. Run under an agent that silently rewrites files during what should be a read-only check. `--no-fix` keeps the check step side-effect free; `checks.py --fmt` is the explicit opt-in that runs `./trunk fmt`.

### Why the i18n script is `i18n.py`, not `locale.py`
A script named `locale.py` in the scripts directory shadows the standard library `locale` module (the script's own directory is first on `sys.path`), which breaks `argparse` in every sibling script.
